# 환경 변화에서 보험 업무 요구로

## 현재 우선순위

[KB IR 근거](research_sources.md)상 장기보험 손익 비중이 크고 자동차는 손실이다. 따라서 첫 실험을 새로운 자산 결제보다 장기보험 업무에도 공통적인 증빙·조건 확인에 둔다. 실제 청구에는 의학적·법적 판단과 사기 조사 등이 더 필요하나 이번에는 행정 필드의 일관성만 다룬다. 자동차는 사고자료 정리·누락 확인이라는 인접 과제가 될 수 있으며 수익개선 효과는 별도 검증 대상이다.

## 연구 결론: 자산 노출과 권리·실행 조건은 별개다

BUIDL은 2024-03-20 출시한 토큰화 private fund share이며 ETF가 아니다. 2026-08-03 발표된 BSTBL은 기존 펀드의 OnChain Shares(BNY가 이전·토큰화 담당), BRSRV는 새 준비자산 활용 지향 펀드(Securitize가 이전·토큰화 담당)다. 공식 본문 확인 범위와 링크는 [조사 기록](research_sources.md#blackrock-상품-구조--2026-11-01-추가-직접-확인)에 있다.

여기서 얻는 연구 해석은 같은 국채 노출도 상품별 환매·권리·양도·수익 조건이 달라질 수 있다는 것이다. 24/7 양도와 24/7 현금화를 구분해야 한다. 보험사는 보유토큰 잔액만으로 현금을 확정하기보다 법적 청구권, 환매 접수·완료, 은행 입금, 시장/서비스 중단 경로를 구분할 필요가 있다는 가설을 세울 수 있다. 준비자산 활용 의도는 무조건적 법적 적격성 보장이 아니다. 이는 KB의 보유 사실이나 사업계획이 아니다.

## 조건부 미래 시나리오

다음은 KB가 실제로 추진한다고 확인한 계획이 아니라 금융환경 연구에서 도출한 가설이다. 관찰신호도 앞으로 확인할 항목이며 이미 측정한 실적이 아니다.

### 1. 고객 AI 상품비교와 API 유통 접점

| 연결 단계 | 가설과 확인 항목 |
|---|---|
| 변화 | 고객 AI가 목적·보장조건을 비교하고 갱신·문의 업무를 중개하면 보험사 자체 화면 밖의 접점이 커질 수 있다 |
| 누구의 수익·비용·위험 | 고객의 탐색비용 감소 가능성, 유통 플랫폼의 중개수익 증가 가능성. 보험사는 고객획득 비용·판매수수료 구조가 바뀌고 가격 비교 압력 및 잘못된 설명의 책임 위험을 부담할 수 있다 |
| KB 기능·필요데이터 | 상품 조건·예외·적용일·출처를 제공하는 API, 동의·대리권 확인, 설명 이력과 상담 인계. 상품/버전 ID, 보장범위, 면책·한도, 고객 요청과 동의 범위가 필요 |
| 성립조건 | 기계가 읽을 조건의 표준화, 고객의 유효한 권한 위임, 비교 품질과 책임 배분, 판매·정보 규제 준수 |
| 반대시나리오 | 복잡한 보장 판단과 신뢰 때문에 고객이 대면 상담을 선호하거나 플랫폼이 폐쇄적이면 API 중심 재편이 제한될 수 있다 |
| 관찰신호 | 실제 제휴 API 공개 범위, AI 경유 견적·상담 비중, 유통수수료 변화, 조건 오설명 민원 및 사람 인계율. 이번 작업에서는 미측정 |

### 2. 권리분화와 공통 인프라 위험

| 연결 단계 | 가설과 확인 항목 |
|---|---|
| 변화 | 시설의 수익권·이용권·담보권이 세분화되어도 여러 계약이 동일 전력·냉각·클라우드에 의존할 수 있다 |
| 누구의 수익·비용·위험 | 자산 운영자·중개자는 조달/거래 기회를 얻을 수 있으나 권리 보유자는 공통 장애에 노출된다. 보험사는 새로운 보장 수요와 함께 동시 손해·보상 중복·귀속 분쟁 위험, 관계 데이터 확보 비용을 검토해야 한다 |
| KB 기능·필요데이터 | 시설-의존성-계약-사고 연결, 유효기간과 권리별 검토, 집적 후보와 미확정 정보 인계. 계약 ID, 권리·피보험이익, 위치/의존성, 해지·변경 이력, 한도·공유한도, 사고 증거가 필요 |
| 성립조건 | 권리와 보상 귀속이 명확하고 의존성 데이터가 최신이며 사건과 손해 사이 관계를 검증할 수 있어야 함 |
| 반대시나리오 | 권리 분화가 제한되거나 위험이 기존 계약으로 충분히 관리되고 데이터 확보 비용이 효용을 넘으면 새 기능의 가치가 작음 |
| 관찰신호 | 신규 권리계약 유형, 공급자 집중도, 공통 장애 피해 계약 수, 중복 보장/손해귀속 분쟁, 의존성 정보 갱신율. 이번 B는 정적 합성 연결만 확인 |

무한에셋은 권리의 세분화·재조합 가능성이지 위험의 무한분산이나 무한한 자본이 아니다. 같은 시설의 서로 다른 계약은 보존하되 계약 합계를 독립 위험 합이나 예상손실로 보지 않는다.

### 3. 디지털자산 현금가용성과 보험금 의무

| 연결 단계 | 가설과 확인 항목 |
|---|---|
| 변화 | 토큰화 지분과 안정코인 준비자산 활용이 늘어도 토큰 이전, 환매, 은행 현금 결제의 운영시간·권리·제약은 다를 수 있다 |
| 누구의 수익·비용·위험 | 운용사·이전대행사는 상품·관리 수익 기회를 얻고 투자자는 수익·이동 편의를 기대한다. 보유 기관은 수탁/이전/환매 비용과 중단·유동성 위험을 부담한다. 보험사는 허용된 자산 운용의 편익과 보험금 지급기일의 불일치 위험을 함께 검토해야 한다 |
| KB 기능·필요데이터 | 보험금 의무의 기일과 자산별 현금화 경로 대사, 법적 청구권·담보잠금·환매 상태·은행 확인의 분리. 상품/클래스/권리자 ID, 환매 창구·마감·결제일, 양도 제한, 담보·동결, 수탁/이전대행/은행 장애 상태가 필요 |
| 성립조건 | 국내 편입/보유/지급 관련 법적 허용, 실제 계약과 청구권 확인, 중단 시 대체 유동성, 외부 확인 데이터 및 책임 주체 확보 |
| 반대시나리오 | 국내 규제·회계·자본비용 또는 운영비가 편익을 넘거나 기존 예금·국채·MMF로 의무를 충분히 관리하면 직접 도입 필요가 약함 |
| 관찰신호 | 허용 상품과 공시 조건 변화, 실제 환매·입금 지연/거절, 주말·장애 시 가용성, 지급기일 대비 유동성 부족 사례. 실제 계좌·법적 적격성·지급 실행은 이번에 미검증 |

미국 제도에서도 GENIUS의 제정/시행, OCC 최종규칙, CLARITY 절차를 분리한다. 추가 확인된 2026-09-15 상원 표결은 심의 개시 동의의 토론종결 부결이며 본안 최종부결이나 폐기를 뜻하지 않는다. 이 사실을 한국 손보의 직접 허용 근거로 사용하지 않는다.

## 기술 역할과 기여 경계

AI는 비정형 자료의 후보 추출·요약·질의 정리를 돕고, 확정된 조건 검사는 룰/SQL로 재현할 수 있다. 이 패키지에는 LLM 호출이나 RAG 성능 비교가 없다. 실제 도입 단계라면 추출 오류, 출처 누락, 불필요한 보류, 개인정보 권한과 인간 인계를 별도로 평가해야 한다.
스마트컨트랙트는 합의된 상태·조건의 기록/실행 수단이 될 수 있지만 잘못된 외부 입력, 법적 권리, 지급능력, 환매시간을 해결하지 않는다. B에서 SQL이 동일 결과를 내므로 그래프DB·에이전트·블록체인을 도입해야 한다는 결론은 나오지 않는다.

사용자 관점의 기여는 기술명을 늘리는 데 있지 않다. 환경 변화에서 어떤 조건을 구분해야 하는지 정의하고, 정상과 예외를 함께 평가하며, 현장 검토자가 필요한 확인 근거를 찾도록 업무를 나누는 것이다.

두 합성 실험은 위 연구 중 조건 확인과 정적 의존성 연결의 일부만 보조한다. 고객 행동·유통 수익·신규 보험 수요·실제 유동성을 검증한 결과로 확장하지 않는다.
