한눈에 보는 문제의식

기존 금융에서는 자료의 누락과 조건 불일치를 정확히 확인하는 일이 중요합니다. 금융이 디지털화되어도 법적 권리, 공통 위험, 실제 현금화 시점은 사라지지 않습니다. 필요한 데이터를 먼저 정의하고, SQL과 규칙으로 확인 가능한 부분부터 작게 검증했습니다.

장기보험의 검토 업무와 자동차 손익 개선

공시 수치는 업무 우선순위에 대한 해석 근거이며 채용 수요나 병목 규모의 직접 측정은 아닙니다. CSM 잔액 10조8,974억원은 현금·당기수익이 아닙니다. KB IR · PDF 26쪽

02 · 업무 문제와 미래 가설

현재의 확인 업무와 미래의 데이터 요구를 함께 봅니다

지급지침 검색·요약, 사고접수, 민원이라는 기존 KB 공개 조사 방향에서 확인 근거와 담당자 인계의 중요성을 읽었습니다. 내부 지급지침은 사용하지 않았습니다. 해당 소개 기사 본문은 이번 재조회에서 점검 안내로 이동했으므로 적용 업무는 이전 조사 요약에 근거하며 생산 시스템·효과 수치를 확인한 것은 아닙니다.

현재 과제: 누락·읽기불가 → 대상·날짜·금액 충돌 확인 → 필요한 근거와 추가 질문을 담당자에게 인계
미래 가설 ① · 유통

고객 AI가 상품 비교를 맡는다면

고객의 탐색비용과 플랫폼의 중개 역할이 바뀌고, 보험사의 획득비용·수수료·설명 책임에도 변화가 생길 수 있습니다.

필요 기능·데이터
조건·예외·적용일·출처 API, 고객 동의와 대리권, 비교·설명 이력, 사람 인계.
성립조건 / 반대시나리오
표준화와 책임 배분이 필요합니다. 대면 신뢰나 폐쇄형 유통이 우세하면 변화는 제한됩니다.
관찰할 신호
AI 경유 견적·상담, 제휴 API 범위, 수수료 변화와 오설명 민원. 이번에는 미측정.
미래 가설 ② · 위험

권리가 나뉘어도 장애는 함께 옵니다

시설 수익권·이용권이 늘면 조달·거래 기회와 함께 공동 장애의 손해귀속·보상 중복 위험이 생길 수 있습니다.

필요 기능·데이터
계약·권리·시설·전력/냉각/클라우드 연결, 유효기간, 한도, 변경 이력과 사고 증거.
성립조건 / 반대시나리오
최신 의존성 정보와 권리 귀속이 필요합니다. 기존 계약으로 충분하거나 확보 비용이 크면 가치가 작습니다.
관찰할 신호
공급자 집중도, 공동 장애 계약 수, 귀속 분쟁과 갱신율. 실험은 정적 연결 일부만 다룹니다.
미래 가설 ③ · 유동성

토큰 잔액을 지급 재원으로 단정하지 않습니다

운용·이전의 편익과 수익 기회가 생겨도 기관은 환매·수탁·중단 위험을 부담합니다. 보험금 의무의 기일과 현금화 경로를 맞춰야 합니다.

필요 기능·데이터
법적 청구권, 담보·동결, 환매 마감/결제일, 은행 입금, 대체 유동성 및 장애 상태.
성립조건 / 반대시나리오
국내 법적 허용·계약 확인이 전제입니다. 기존 예금·국채·MMF가 충분하면 도입 필요가 약합니다.
관찰할 신호
환매·입금 지연, 주말/장애 시 가용성, 지급기일 불일치. 실제 계좌·지급은 미검증.

이 세 가지는 KB의 실제 사업계획이 아닌 조건부 연구 가설입니다. ‘무한에셋’은 권리의 세분화·재조합 가능성이며 위험의 무한분산을 뜻하지 않습니다. 계약 한도의 합도 예상손실이 아닙니다.

03 · 필요한 기술과 실제 검증

관계를 먼저 정의하고, SQL로 충분한 부분부터 확인했습니다

AI는 자료 후보 추출·요약을 보조할 수 있고, 확정 조건은 SQL·규칙으로 재현할 수 있습니다. 다기관 공유원장은 공통 의미·권한·책임에 대한 합의가 있을 때 별도로 평가할 선택지입니다. 이번에는 LLM 모델, RAG, 스마트컨트랙트의 성능을 비교하지 않았습니다.

실험 A · 현재 업무의 작은 보조 사례

합성 청구 증빙의 행정검사

사전에 정의한 행정검사 기능을 16개 합성 사례로 재현했습니다. 이유 집합은 16/16 일치했고 정상 사례의 불필요 보류는 0/8이었습니다. 필수값·읽기불가·대상·날짜·규칙·금액·문서 누락을 구분하고 관련 필드를 인계합니다.

기본 접수 SQL은 검사 기능이 더 적어 이유 일치가 9/16입니다. 같은 작성자가 정답을 알고 구현한 평가이며 독립 정확도 성과가 아닙니다. 정상 8건은 두 규칙 패턴의 금액 변형입니다. 실제 KB 약관·OCR·의학 판단은 검증하지 않았습니다.

정상 상태도 지급승인이 아닙니다. 모든 결과는 담당자 검토가 필요하며 실제 지급 권한을 부여하지 않습니다.

실험 B · 미래 요구의 작은 보조 사례

시설 의존성과 권리의 연결

가상 데이터센터 3곳·권리계약 24개를 대상으로 평가 사건 4개의 영향 계약과 알려진 한도 소계를 확인했습니다. 1단계 공통 의존성 조회에서 SQL과 Python 결과가 4/4 일치했습니다.

자산별 집계와 의존성 조인은 다른 업무 질문에 답합니다. 기능 차이를 알고리즘 우열로 해석하지 않습니다. 소계는 합성 노출이며 예상손실·보험료·지급금이 아닙니다. 해지·변경 이력·공유한도·다단계 전파는 미구현입니다.

한도 누락과 모르는 권리종류를 별도 표시했습니다. SQL로 충분한 범위이며 블록체인의 필요성을 입증하지 않습니다.

검증의 경계와 실패에서 얻은 기준
별도 확인기록과 해석
단위시험기간 경계, 0과 누락, 중복, 지급승인 차단 등 8개 통과. 평가 사례 수와 합산하지 않습니다.
이전 공개 안내 검색보수적 분류를 추가한 방식에서 정상 질문 8개 중 4개를 불필요하게 보류했습니다. 정상 사용성을 해칠 수 있다는 부정 결과를 보존했습니다.
측정하지 않은 것직원 시간·비용 절감, 실제 고객 효과, 운영 정확도, 독립 표본 일반화, 법률 적격성.

정답·입력 고정 → 코드 고정 → 개발 실행 → 코드 변경 없는 평가 1회 순서를 기록했습니다. 작성자가 정답을 알고 있었으므로 사전 고정은 독립 평가를 의미하지 않습니다. 분모·원결과·재현법

04 · 자기소개서에서 연결할 기여

금융의 질문을 데이터 기준과 확인 가능한 업무로 바꾸겠습니다

금융환경을 연구하며 구분한 권리·조건·시점을 보험 업무의 데이터 요구로 연결했습니다. 필요한 확인 항목과 예외를 먼저 정의하고, AI의 구현 지원을 받아 작은 합성 사례로 재현 가능성을 점검했습니다.

이 프로젝트에서 한 일

사용자는 금융 변화와 현재 병목을 직무 기여로 연결하려는 문제의식·방향을 정했습니다. AI가 공개자료 정리, 합성 입력·정답 작성, 코드 구현과 시험을 지원했습니다.

혼자 수행한 독립 개발·실무 운영 경험으로 주장하지 않습니다. 지원 문장은 실제 참여와 설명 가능한 범위를 확인해 사용해야 합니다.

입사 후 기여로 연결할 방향

  1. 담당자와 정상 처리·추가 확인·인계의 경계를 합의합니다.
  2. 출처·버전·대상·시점이 추적되는 데이터를 정리합니다.
  3. 별도 평가자가 만든 표본으로 누락과 불필요 보류를 함께 평가합니다.

내부 업무·권한·데이터를 먼저 확인해야 하는 제안이며 이미 달성한 현장 성과가 아닙니다.
