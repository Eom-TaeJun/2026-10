# 1쪽 — 환경: 보험의 현재 수익과 미래 접점

**연구 결론: 권리가 디지털화·세분화되어도 실행 조건과 공통 위험은 사라지지 않는다.**

- BUIDL의 사모 펀드 지분과 BSTBL·BRSRV의 상품 구조를 구분했다. 같은 국채 노출이어도 권리·환매·양도 조건은 별도 확인해야 하며 24/7 양도는 24/7 현금화를 뜻하지 않는다.
- KB손보 2026년 1~9월 별도 보험손익: 장기 7,411억원, 일반 486억원, 자동차 -476억원. 장기보험의 반복 검토 업무부터 작은 과제를 정했다.
- 권리가 쪼개져도 공동 시설 위험은 남는다. 고객 AI가 비교·관리를 맡으면 보험사 접점은 신뢰 가능한 조건 정보와 API로 바뀔 수 있다.
- 현재 수치는 공시, 미래 접점은 조건부 가설이다. CSM을 현금으로 해석하지 않는다.

근거: [KB IR 등 공개 조사](research_sources.md), [미래 시나리오](future_scenarios.md).

# 2쪽 — 문제: 같은 금액·같은 자산이어도 조건은 다르다

**대상·시점·권리를 구분하지 않으면 확인해야 할 예외를 놓친다.**

- 현재: 증빙 누락/읽기불가, 대상·금액 충돌, 사건일에 맞지 않는 문서 조건을 담당자에게 전달해야 한다.
- 유통: 고객 AI가 비교를 맡는다면 보험사에는 조건·출처·권한이 명확한 API와 사람 인계가 필요할 수 있다.
- 유동성: 토큰 잔액보다 법적 청구권·환매 완료·은행 현금 확인을 보험금 의무의 기일에 연결해야 한다는 가설을 세웠다.
- 미래: 시설이 달라도 전력·냉각·클라우드 장애가 여러 계약에 영향을 줄 수 있다. 만료·중복·한도 미상을 따로 확인해야 한다.
- AI는 문서 후보 추출과 정리를 보조할 수 있고 확정 조건은 SQL/룰로 확인할 수 있다. 공유원장은 여러 기관의 합의·책임·권한이 필요한 경우에만 별도 가치 검증한다.

공개 기사 접근 실패와 내부 지급지침 부재를 표시했다. 실제 지급 판단은 다루지 않았다.

# 3쪽 — 검증: 먼저 정답과 분모를 정하고 작은 시험을 했다

| 평가 | 결과 | 의미 |
|---|---|---|
| 합성 청구 사례 | 사전에 정의한 행정검사 기능 16개 사례를 재현; 이유 16/16 일치, 정상 불필요보류 0/8 | 기준선 기능이 더 적으며 단일 작성자가 정답을 알고 구현한 known evaluation. 독립 정확도 성과 아님 |
| 시설 3곳·계약 24개, 사건 4개 | SQL/Python 영향·소계 4/4 일치 | SQL로도 충분한 의존성 기능 |
| 경계 조건 단위시험 | 8/8 통과 | 기간·0/누락·중복 구별 |

기본 접수 SQL 이유 일치는 9/16이었다. 자산별 SQL과 의존성 SQL은 업무 질문이 다르므로 알고리즘 우열로 표현하지 않는다. 동일 작성 주체의 합성 규칙 재현이며 실제 정확도·시간 절감·LLM 성능이 아니다. 이전 검색 실험 B의 정상 질문 불필요보류 4/8도 숨기지 않았다.

# 4쪽 — 기여: 기술 선택보다 검토 기준을 먼저 설계한다

**금융의 조건을 데이터 기준·근거·담당자 인계로 바꾸는 기여를 지향한다.**

AI가 조사·합성 데이터·코드 구현·시험을 보조했다. 실제 운영 시스템 구축이나 효과 측정 성과로 해석하지 않는다.

연구 시나리오마다 이해관계자의 수익·비용·위험, 필요한 데이터, 성립조건, 반대시나리오와 관찰신호를 정리했다. 이는 KB의 실제 사업계획이 아니다.

다음 현장 검증은 담당자와 실제 확인 항목을 합의하고 독립적인 표본으로 누락과 불필요보류를 평가하는 일이다. 고객 AI 접점에서도 조건·출처·권한이 분명한 정보를 제공하고, 판단이 필요한 경우 정확한 근거와 함께 사람에게 넘기는 방향을 제안한다.

실제 보험금 지급, 법률 판단, 공유한도·해지/의존성 이력, 운영 효과는 미검증.
