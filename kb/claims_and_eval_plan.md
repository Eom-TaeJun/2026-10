# 주장과 사전 평가계획 — 2026-11-01

## 잠정 주장
A. 금융 연구에서 구분한 대상·조건·시점을 합성 청구 증빙의 행정적 일관성 검토에 적용하면, 누락/읽기불가/대상·날짜·금액 충돌을 근거 필드와 함께 인계할 수 있다.
B. 권리가 세분화되어도 공통 시설 의존성은 사라지지 않는다. 의존성·계약 유효기간·권리종류를 연결하면 사건별 영향 계약과 미확정 정보를 구분할 수 있다. 이는 SQL로도 구현할 수 있는 기능 가설이다.

## 고정 규칙과 데이터
실제 고객·의료·계좌·약관 없음. 금액은 합성 값. A 규칙 v1은 2026-01-01 이상 07-01 미만, v2는 07-01 이상 2027-01-01 미만. v1 필수문서 application/identity_stub, v2는 event_proof 추가. 청구 대상과 증빙 대상 일치, 금액 일치, 문서 읽기 가능을 확인. 정상도 지급승인이 아니며 담당자 검토 필요.
A 개발 8건/평가 16건(정상 8, 예외 8). 정답 이유 집합은 데이터 작성 시 수작업 명시. 동일 템플릿 기반이라 독립 모집단 표본이 아니다. 기준선은 같은 입력의 날짜·금액 존재와 application만 검사하는 SQL 접수검사. 개선 규칙과 기능 범위가 다르므로 AI 모델 성능 향상으로 부르지 않는다.
B 데이터센터 3곳, 서로 다른 권리계약 24건과 완전중복 1행. 개발 사건 2/평가 사건 4. 각 사건의 영향 ID와 알려진 한도 소계를 수작업으로 먼저 고정한다. 단순 자산별 SQL과 의존성·시간·권리 SQL 모두 같은 전체 데이터를 받는다. Python 규칙 결과와 SQL 결과의 일치도 확인한다. 자산별 집계는 다른 질문에 답하는 기능 기준선이며 우수한 알고리즘의 증거가 아니다.
B 기간은 시작 포함/종료 제외. 같은 계약 ID 중복은 한 번만, 같은 시설의 서로 다른 계약은 각각 유지. 한도 누락은 0으로 확정하지 않으며 모르는 권리종류는 별도 검토. 한도 합계는 예상손실/지급금/보험료/수익이 아니다.
