# KB손해보험 AI·데이터 지원용 증거 패키지

금융환경 연구의 결론은 권리가 디지털화·세분화되어도 법적 권리, 실행 조건, 공통 위험과 현금화 시점은 따로 확인해야 한다는 것이다. 현재 병목과 미래 업무 가설을 먼저 정의하고, 작은 합성 실험은 그중 일부 행정검사 기능만 재현했다. 실제 KB 운영 시스템·지급 판단·실무 절감 성과를 주장하지 않는다. 사용자 문제정의에 AI가 조사·코드·시험을 보조했다. 작성/실행: 2026-11-01 UTC.

제출용 읽기 순서: [단일 HTML 포트폴리오](portfolio.html) → [자기소개서 주장 설계](application_claims.md) → 아래 연구·검증 근거. HTML은 다운로드 후 브라우저에서 열 수 있다.

## 1. 환경

현재 KB손해보험의 장기보험 중심 손익 구조에서 출발한다. 2026년 1~9월 별도 보험손익은 장기 7,411억원, 일반 486억원, 자동차 -476억원이다. CSM 10조8,974억원은 가용현금이 아니다. [공개 근거·접근 제한](research_sources.md)에 숫자와 출처의 범위를 구분했다.

앞으로 권리가 세분화되고 고객 AI가 비교·관리 접점을 맡는다면, 보험사는 신뢰할 조건 정보와 API, 사고·권리·공통 의존성 데이터를 더 명확히 제공해야 할 수 있다. 이는 예측 확정이 아닌 [조건부 시나리오](future_scenarios.md)다. 미국 법의 제정·시행·진행단계를 한국 보험사의 권한으로 옮기지 않는다.

BUIDL·BSTBL·BRSRV의 상품 구조를 비교해 국채 노출과 지분의 권리·환매·양도 조건을 구분했다. 24/7 양도는 24/7 현금화가 아니다. [미래 시나리오](future_scenarios.md)는 고객 AI/API 유통, 권리분화·공통 인프라 위험, 디지털자산 현금가용성·보험금 의무의 세 갈래를 변화→이해관계자의 수익·비용·위험→KB 기능/데이터→성립조건→반대시나리오→관찰신호로 정리한다. KB의 실제 사업계획을 주장하지 않는다.

## 2. 문제

현재 업무의 보조 과제는 청구·증빙의 누락과 충돌을 구분하고 확인 근거를 담당자에게 넘기는 것이다. 지급지침 검색·요약, 사고접수, 민원이라는 기존 공개 조사 방향과 연결하되 내부 지침을 사용하지 않는다. 해당 KB 기사 원문은 이번 점검에서 유지보수 안내로 이동했으므로 재검증 실패도 표시했다.

미래 과제는 같은 전력·냉각·클라우드에 의존하는 시설과 서로 다른 권리계약의 연결이다. 자산 하나씩 보는 집계만으로는 다른 시설의 공통 장애와 계약 기간·권리 차이를 표현하지 못한다. 블록체인은 이 문제의 필수 조건이 아니며 단일기관 SQL/API부터 비교한다.

## 3. 검증

[주장과 사전 평가계획](claims_and_eval_plan.md) → 정답/데이터 SHA 고정 → 최소 구현 → 개발 실행 → 코드 변경 없는 평가 1회 → [원결과와 한계](results/summary.md) 순서로 수행했다.

| 합성 실험 | 결과 | 해석 |
|---|---|---|
| A: 행정 증빙 검토 | 사전에 정의한 행정검사 기능 16개 사례를 재현. 이유 일치 기본 접수 SQL 9/16, 조건 규칙 16/16; 정상 불필요보류 둘 다 0/8 | 기준선 검사 기능이 더 적다. 단일 작성자가 정답을 알고 구현한 known evaluation이며 정확도 개선·독립 평가가 아님 |
| B: 시설 3곳/계약 24개, 평가 4사건 | 의존성 Python/SQL 모두 영향집합·알려진 한도 4/4 일치. 자산별 SQL 0/4 | 기능과 데이터 모델 차이. SQL로 충분한 구현 범위 |
| 경계/결측/중복 시험 | 8/8 통과 | 0한도·누락, 기간 경계 등 제한된 조건 |
| 이전 공개 안내 검색 | 정상 A 근거 7/8, B 불필요보류 4/8 | 부정 결과를 [별도 보존](results/prior_negative_experiment.md). 이번 수치와 합산 안 함 |

같은 작성 주체의 소규모 합성 데이터다. 실제 고객자료·의료정보·실계좌·자금 사용 없음. 사람 검수시간·비용절감 측정 없음. 읽기불가 표식은 OCR 실행이 아니다. 공유한도·해지·의존성 변경 이력은 미구현이다. 재현 명령은 [실행 요약](results/summary.md#재현), 입력/구현은 [experiments](experiments), 원결과는 [JSON](results/eval.json)/[CSV](results/eval.csv)에 있다.

## 4. 기여

지원 메시지는 “새 기술을 써 봤다”보다 “금융 조건을 구분하고, 검증 가능한 데이터 기준과 담당자 인계 구조를 설계했다”에 둔다. [지원 문장과 기여 구분](application_evidence.md)에서 사용자 관점과 AI 구현 지원을 구분했다. 실험이 반증하지 못한 일반화·현장효과는 남겨 둔다.

| 4쪽 구성 | 기존 네 주제의 연결 | 산출물 상태 |
|---|---|---|
| 환경 | 현재 KB AI 업무, 무한에셋 기회, 고객 AI 접점 변화 | 공개 근거와 검증 실패 표시 완료 |
| 문제 | 현재 검토 병목과 미래 공동 의존성, AI/스마트컨트랙트 역할 경계 | 조건부 시나리오·기술 선택 기준 완료 |
| 검증 | SQL/룰 최소 구현과 정상·예외 평가 | 사전고정·실행·원결과·부정 결과 보존 완료 |
| 기여 | 고객 AI 시대의 신뢰 정보/API, 조건·근거·인계 설계 | 지원 표현·제한·기여 주체 정리 완료 |

두 구성은 위 표로 연결했다. 짧은 발표본은 [4쪽 포트폴리오](portfolio_4pages.md)다. Library 입력의 공식 다운로드는 실패하여 해당 원문을 소비하지 않았고, 비공개 원문을 포함하지 않았다. 사용자 승인 범위는 이 공개 연구·합성실험 패키지의 GitHub 반영이며 지원서 제출이나 별도 호스팅 설정은 포함하지 않는다.
