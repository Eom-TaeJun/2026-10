# 자기소개서 주장 설계 — 제출 전 검토용

완성된 지원서나 제출 완료 문서가 아니다. [단일 HTML 포트폴리오](portfolio.html)의 주장을 짧게 연결한 초안이며, 상세 귀속·금지할 확대는 [application_evidence.md](application_evidence.md)를 따른다.

| 항목 | 사용할 사실 범위 |
|---|---|
| 핵심역량 한 문장 | 금융의 권리·조건·시점을 구분하고 이를 데이터 요구·확인 기준·담당자 인계로 연결하는 문제정의 역량을 지향한다. |
| 왜 KB 현업인가 | 장기보험 중심 손익 구조와 기존 공개 조사상의 검색·요약/사고접수/민원 업무를 연결했다. KB 소개 기사 재조회 실패와 내부 지침 미접근을 명시했으며 실제 병목 크기·채용 기준을 측정하지 않았다. |

## 사실 범위 안의 지원 문장 초안 3개

1. 금융환경을 연구하며 권리·적용 조건·효력 시점을 구분하는 관점이 중요하다고 보았습니다. 이를 보험 업무의 데이터 요구로 연결하고, AI의 구현 지원을 받아 합성 증빙의 누락과 충돌을 확인하는 작은 실험으로 구체화했습니다.
2. 권리가 세분화되어도 같은 인프라의 장애가 여러 계약에 함께 영향을 줄 수 있다는 가설을 세웠습니다. 가상 시설과 계약의 의존성·기간·권리를 연결했고 SQL도 Python 규칙과 같은 결과를 내는 범위를 확인하며, 필요한 관계를 먼저 정의하는 기술 선택을 연습했습니다.
3. 정상 질문을 과도하게 보류한 이전 실험 결과도 보존하면서 누락 탐지뿐 아니라 불필요한 인계도 평가해야 한다고 정리했습니다. 현업에서는 담당자와 기준을 합의하고 별도 표본으로 검증하여, 확인 근거가 추적되는 데이터 업무에 기여하고 싶습니다.

실제 본인 참여 내역과 코드·결과를 설명할 수 있는 범위를 확인한 뒤 문장을 사용한다. AI 보조 구현을 독립 개발 경력으로, 합성 규칙 재현을 실제 운영 성과로 바꾸지 않는다.
